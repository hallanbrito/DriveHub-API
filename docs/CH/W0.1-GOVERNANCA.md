### Estratégia de Reversão Auditável (Compatível com Squash Merge)
- **Pós-Integração (Caso W0.1 seja integrada via Squash Merge na `main`):**
  - Reversões pós-integração nunca devem ser executadas com push direto na `main`. O procedimento seguro e auditável exige abertura de branch isolada e submissão via Pull Request:
    ```bash
    # 1. Atualizar base local a partir da main integrada
    git checkout main
    git pull origin main

    # 2. Criar branch isolada de rollback
    git checkout -b revert/w0-1-governanca-ci main

    # 3. Executar reversão auditável do squash commit consolidado (sem flag -m)
    git revert <squash-commit-sha>

    # 4. Publicar a branch e abrir Pull Request para validação de CI e aceite formal
    git push origin revert/w0-1-governanca-ci
    gh pr create --title "revert(w0.1): reversão da blindagem de CI" --body "..."
    ```
  - **Atenção técnica à sintaxe:** O commit consolidado por Squash Merge possui pai único (não é merge commit). Portanto, `git revert <squash-commit-sha>` deve ser executado **sem** a flag `-m` (que no `git revert` é `--mainline <parent-number>` para indicar número do pai em commits de merge e causa erro quando usada indevidamente).
  - **Validação e Gates:** O PR de reversão aciona a esteira de CI (`Django Checks & Pytest (Python 3.12)`), garantindo que o estado revertido passa nos testes.
  - **Aprovação e Integração:** A reversão só pode ser mesclada na `main` após revisão técnica independente e aceite formal do PO.
  - **Vedação:** É expressamente vedado utilizar `git reset --hard` na `main` ou realizar push direto sem Pull Request.
- **Pré-Integração (na branch isolada `agy/w0-1-governanca-ci`):**
  - Descarte seguro via fechamento do Draft PR e exclusão da branch remota, preservando a integridade da `main`.
